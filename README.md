<h1 align="center">G2 IMEI Generator</h1>

<p align="center"><img src="docs/screenshots.png" alt="Generate, browse and check screens"></p>

An Android app (Kivy + Buildozer) with a black and gold design that generates **checksum-valid test IMEIs** and looks up
TACs against an **embedded, offline TAC database** of 22,500+ device types from 560+ brands.
It has a preset for eSIM-capable iPhones.

**Built by [IamG2](https://github.com/G33l0/IamG2).**

---

## What it is (and isn't)

It generates numbers. It is **not** an IMEI changer. It produces 15-digit strings that pass
the Luhn checksum and start with a real TAC (Type Allocation Code). It does **not** write to
device hardware, activate eSIM profiles or get around carrier restrictions. Android doesn't
let apps change a phone's IMEI.

It's meant for QA, test fixtures, form-validation testing, teaching and development work
that needs device identities that look realistic. Using a generated IMEI on a live network,
or to pretend to be a real device, is illegal in most countries.

## Features

**Generate**
- **Embedded TAC database** (`data/tac.sqlite`, about 2 MB). Works fully offline and is bundled inside the APK.
- Three sources:
  - **eSIM iPhone**: verified Apple TACs for eSIM models (XR / XS / 11 and later / SE 2nd and 3rd gen)
  - **Database**: pick a brand, or choose **Any brand** to search every brand at once (for example "galaxy s9", "iphone" or a TAC prefix)
  - **Custom TAC**: any 8-digit TAC, labelled with its device name if the TAC is known
- **Favourites**: tap the star next to a model or TAC. Favourites appear as one-tap chips above the generator.
- **Batch generation** of 1 to 1000 IMEIs, all different within a batch, using a cryptographically secure RNG. Use the − / + stepper or the **1 · 10 · 50 · 100** shortcut chips.
- **Copy formats**: one per line, CSV (`imei,tac,model`), JSON array, quoted list (`'…', '…'`) or comma list. **Copy**, **Share** (Android share sheet) and **Save** (desktop) all use the format you pick. Tap any single row to copy just that IMEI.

**History**
- Every batch is saved on the device (the most recent 100). Tap a batch to open it again, copy it in the current format, or delete it.

**Check**
- **Single**: checks one IMEI (spaces and dashes are fine) and shows one of four verdicts:
  - **Valid IMEI**: well-formed, and its TAC is a known device (brand and model are shown).
  - **Valid format, unknown device type**: well-formed, but the TAC isn't in the database.
  - **Valid test IMEI**: starts with `00`, which is reserved for test equipment.
  - **Invalid IMEI**: not a well-formed IMEI.

  It also shows who allocated the TAC (for example BABT (UK) for `35…`) and flags placeholder-looking numbers. **Paste** checks the clipboard straight away.
- **Bulk**: paste a list (one per line, or separated by commas, semicolons or tabs; JSON and quoted lists work too). You get counts of valid, unknown and invalid entries, each number with its device, **Copy valid** / **Copy invalid**, and a CSV report to share. Up to 5,000 entries per check.
- **What "valid" means:** every IMEI carries a built-in consistency digit, so changing any single digit of a valid number always makes it invalid. That's how typos are caught, and it's expected, not a false positive. A valid number is only *well-formed*: whether it belongs to a real phone can only be confirmed by the network operator or the GSMA. The app never shows how it verifies numbers.

**Online database updates**: on startup (and when you return to the app after 6+ hours) the app checks for a newer TAC database in the background. If one exists, it downloads it, verifies it (size, checksum, row count, data hash) and switches to it without a restart. The header shows **Online** (green dot) or **Offline**. With no connection the app keeps working on the last database it has, either the bundled one or the last downloaded update, whichever is newer. **Check → Update database** checks on demand.

**Exit**: the **Exit** button (top right) or the Android back button asks before closing. On the Check and History tabs, back returns to Generate first.

**Remembers your setup**: the last tab, source, brand, search, model, custom TAC, quantity, copy format and Check mode are restored when you reopen the app.

Also works from the command line: `python imei_generator.py 35104463 10`

## Design

Black and gold theme: background `#0B0B0C`, cards `#141416`, gold `#D4AF37`, ivory text
`#F2EDE3`. Type is set in **Manrope** (interface), **Space Grotesk** (headings, logo) and
**JetBrains Mono** (numbers), all bundled under the SIL Open Font License (`assets/fonts/`).
Generated IMEIs are shown with the TAC (device type) in gold and the rest in ivory. Tap any row to copy that single IMEI.

The logo is a gold SIM-card outline with a G2 monogram. It's generated by
`tools/make_logo.py`, which outputs `assets/logo.png`, the launcher icons (legacy plus
adaptive foreground and background) and the presplash. Edit the script and re-run it to tweak the mark.

## About the TAC data

The database comes from the **[Osmocom TAC database](http://tacdb.osmocom.org)**
(CC-BY-SA 3.0, © Harald Welte and contributors), plus any TACs you add yourself in
`data/tac_extra.csv`.

> **Correction to earlier versions:** the old `tac_db.json` had TACs that couldn't be
> verified. Most weren't in any public source, the same TAC was listed for several models,
> and `35332510` is actually a **Samsung Galaxy S9 (SM-G960F/DS)**, not an iPhone. That
> file has been removed.

Public data on recent iPhones is thin. Osmocom has these eSIM iPhone TACs:

| TAC      | Model                |
|----------|----------------------|
| 35727609 | iPhone XS Max        |
| 35292511 | iPhone 11 (A2221)    |
| 35657310 | iPhone 11 (A2221)    |
| 35104463 | iPhone 13            |

To cover more models (XR, 12, 14, 15, 16, SE), add TACs you have verified to
`data/tac_extra.csv`. Good sources are the first 8 digits of the IMEI on a test device you
own (*Settings > General > About*, or dial `*#06#`), or a box label.

```csv
tac,brand,model,aka,esim
35XXXXXX,Apple,iPhone 15,A3090,1
```

Then rebuild the database (see below). The official GSMA IMEI database is paid and
restricted, so don't scrape it.

### How online updates are published

`.github/workflows/update-tac-db.yml` rebuilds the database every Monday, whenever
`data/tac_extra.csv` changes on `main`, or when run by hand (**Actions → Update TAC
database → Run workflow**). If the data actually changed, it commits the new
`data/tac.sqlite` and `data/tac_manifest.json`. Phones pick the update up the next time
the app starts. So to push new verified TACs to every installed app, add them to
`data/tac_extra.csv` and merge. No new APK is needed.

The app reads the manifest from
`https://raw.githubusercontent.com/G33l0/imei-generator/main/data/tac_manifest.json`,
so the repository must be public for updates to work (the URL is set in `dbupdate.py`).

## Setting up the APK with the full TAC database embedded

The database is a normal file at `data/tac.sqlite`, and `buildozer.spec` already packages it
(`source.include_exts` includes `sqlite`, and the `sqlite3` recipe is in `requirements`). A
ready-built copy is committed, so **every APK you build already has the full database**. You
only need step 1 if you want to refresh it or add your own TACs.

### 1. (Optional) Refresh or extend the database

```bash
python3 tools/build_tac_db.py                 # downloads the latest Osmocom CSV + merges tac_extra.csv
# or, offline / behind a proxy:
curl -o tacdb.csv http://tacdb.osmocom.org/export/tacdb.csv
python3 tools/build_tac_db.py --csv tacdb.csv
# only your own TACs, no Osmocom:
python3 tools/build_tac_db.py --no-osmocom
```

The script prints the result, for example:
`Wrote data/tac.sqlite: 22524 TACs, 566 brands, 4 eSIM iPhone TACs (osmocom)`.

### 2. Build the APK

#### Option A: GitHub Actions (easiest, nothing to install)

This repo includes `.github/workflows/build-apk.yml`.

1. Push to `main` (or open **Actions → Build APK → Run workflow**).
2. Wait for the run to finish. The first build takes about 20–30 minutes; later runs are faster because the cache is reused.
3. Download the **g2-imei-generator-apk** artifact from the run page and unzip it. You'll get `g2imeigen-1.3.0-arm64-v8a_armeabi-v7a-debug.apk`.

If the GitHub build fails, open the failed run, expand **Build debug APK** and scroll up from
the red "Buildozer failed" box; the real error is above the environment dump. The workflow
uses Node 24 actions and builds on Ubuntu 24.04 (see the comment at the top of
`.github/workflows/build-apk.yml` to build on Ubuntu 26.04 instead).

**Build notes.** `buildozer.spec` pins python-for-android to `v2026.05.09` and uses a small
Kivy recipe override in `p4a-recipes/kivy/`. The override removes Kivy's unused `requests`
dependency, whose Android-only `charset-normalizer` wheel otherwise stops the build with
"*…android_24_arm64_v8a.whl is not a supported wheel on this platform*". A second fix,
`tools/pip-constraints.txt` (used as `PIP_CONSTRAINT`), keeps pip at the version bundled with
python-for-android, so its venv isn't left half-upgraded when it builds the second CPU type
("*ImportError: cannot import name 'BuildDependencyInstallError'*"). Keep all three settings
when changing the build.

#### Option B: Linux / WSL2 (recommended for local builds)

```bash
sudo apt update
sudo apt install -y python3 python3-pip python3-venv git zip unzip openjdk-17-jdk \
    autoconf automake libtool libltdl-dev pkg-config zlib1g-dev libncurses-dev cmake libffi-dev libssl-dev

git clone https://github.com/G33l0/imei-generator.git
cd imei-generator

python3 -m venv .venv && source .venv/bin/activate
pip install --upgrade pip setuptools wheel
pip install buildozer "cython<3"

python -m unittest discover -s tests       # optional sanity check
export PIP_CONSTRAINT=$PWD/tools/pip-constraints.txt   # see build notes
buildozer -v android debug                 # first run downloads the SDK/NDK (~3 GB)
```

The APK is written to `bin/`. **Don't run `buildozer init`.** That would overwrite the
`buildozer.spec` that's already set up.

#### Option C: Termux (experimental)

Buildozer doesn't officially support building on Android itself, and NDK toolchains often
fail there. Use Option A from your phone instead: push the code, then download the APK
from the Actions page.

### 3. Install on your phone

- **USB:** `adb install -r bin/*.apk` (turn on USB debugging first), or `buildozer android deploy run logcat`
- **Manually:** copy the APK to the phone, open it, and allow *Install unknown apps* for your file manager.

### 4. Check that the database is embedded

Open the app, go to **Check → Single**, and look at the footer. It should say
`Database: 22,524 TACs …`. If it says `[database not loaded …]`, the APK was built
without `data/tac.sqlite`. Check that the file exists and that `sqlite` is still listed in
`source.include_exts`. Even then the app keeps working, using a small built-in fallback list.

### Signed releases (automatic, via GitHub Actions)

Push a version tag and GitHub builds a **signed** APK and publishes it on the repo's
**Releases** page with a SHA-256 checksum. The app version is taken from the tag.

**One-time setup:**

1. Create a signing key on your computer. Keep this file and its passwords safe: every
   future update must be signed with the same key, or phones will refuse to install it.
   ```bash
   keytool -genkey -v -keystore release.keystore -alias g2imei -keyalg RSA -keysize 2048 -validity 10000
   base64 -w0 release.keystore > release.keystore.b64      # macOS: base64 -i release.keystore
   ```
2. In GitHub go to **Settings → Secrets and variables → Actions → New repository secret** and add:

   | Secret                       | Value                                   |
   |------------------------------|-----------------------------------------|
   | `ANDROID_KEYSTORE_BASE64`    | contents of `release.keystore.b64`      |
   | `ANDROID_KEY_ALIAS`          | `g2imei` (the alias you chose)          |
   | `ANDROID_KEYSTORE_PASSWORD`  | the keystore password                   |
   | `ANDROID_KEY_PASSWORD`       | the key password (often the same)       |

**Each release:**

```bash
git tag v1.3.0
git push origin v1.3.0
```

When the workflow finishes, **Releases → v1.3.0** has `g2imeigen-1.3.0-…-release.apk` and its
`.sha256` file. If the secrets are missing, the job stops with a message saying which ones to add.

**Signing locally instead:**

```bash
export P4A_RELEASE_KEYSTORE=$PWD/release.keystore P4A_RELEASE_KEYALIAS=g2imei
export P4A_RELEASE_KEYSTORE_PASSWD=... P4A_RELEASE_KEYALIAS_PASSWD=...
buildozer android release
```

Never commit the keystore or the `.b64` file. `*.keystore` and `*.b64` are in `.gitignore`.

## Running on desktop / development

```bash
pip install kivy==2.3.1
python main.py                              # desktop window
python -m unittest discover -s tests -v     # tests: generation, DB, formats, bulk, user data
python imei_generator.py 35104463 5         # CLI: 5 IMEIs for TAC 35104463
```

## Project layout

```
main.py               app logic (Generate, Check, History)
g2.kv                 layout and black/gold styling
imei_generator.py     validation and batch generation (no Kivy dependency)
exporters.py          copy/share formats, bulk-check parsing and reports
userdata.py           on-device settings, favourites and history (SQLite)
dbupdate.py           background TAC database updates (download, verify, swap)
tacdb.py              read-only access to data/tac.sqlite (with built-in fallback)
data/tac.sqlite       embedded TAC database (generated, committed)
data/tac_extra.csv    your own verified TACs, merged at build time
data/tac_manifest.json describes the current database for in-app updates
tools/build_tac_db.py builds data/tac.sqlite from Osmocom + tac_extra.csv
p4a-recipes/kivy/     Kivy build-recipe override (see "Build notes")
tools/make_logo.py    renders logo, launcher icons and presplash into assets/
assets/               logo, icons, presplash, bundled fonts (OFL)
tests/                unit tests
buildozer.spec        Android build config
```
